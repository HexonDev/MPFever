Preview release from `codex/lua-optimizations`, based on this fork's .NET 10 migration and launcher optimizations.

### Changes

- Windows x64 player and dedicated-server packages include the .NET 10 runtime; no separate .NET installation is required.
- Lua result/binding readers keep their handles open, pending-display reads are throttled, and unchanged AI configuration is cached.
- The recursive state-size diagnostic is opt-in (`MPFEVER_STATEPROFILE=1`). Deterministic hashes, lockstep barriers and command ordering are retained.
- Manual **Local test (2 games)** opens independent launchers and normal Host/Join menus.
- An opt-in Lua/native/named-pipe/C# ping/pong probe is included. Run `start-pipe-probe.bat` from the extracted player folder to try it.

### Scope and testing

The pipe probe is **disabled by default**. Ordinary multiplayer still uses file IPC.
Ping/pong was observed in both local games' main-menu Lua states on the verified GOG executable (PE stamp `0x6ad9e27e`).
The native binding disables itself on other executables. Loaded-game UI/simulation probing and gameplay transport replacement remain experimental/unverified.
The probe currently disconnects after 30 seconds of inactivity and uses process-lifetime native cleanup; it has no acknowledged shutdown handshake.
Operation-count reductions do not establish a particular FPS/latency gain or fewer desyncs.

Release checks cover the complete self-contained publish output, Lua 5.2 scripts, native pipe queue/binding behavior, malformed/fragmented frames,
timeouts and package contents. Windows `Sleep` duration is recorded as a diagnostic; timer API success and the disable switch remain mandatory tests.

Extract the entire archive and keep all runtime DLLs and language folders beside `MPFever.exe`.
All players in a session should use the same MPFever version. This is a prerelease and is excluded from the automatic stable-release updater.

The fork's application/native binaries are **not code-signed**: SignPath is not configured for this repository.
Bundled Microsoft runtime files retain their original signatures and license notices.
